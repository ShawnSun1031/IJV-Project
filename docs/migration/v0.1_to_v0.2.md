# Migration Guide: v0.1 to v0.2

This guide helps you migrate from IJV Project v0.1 (binary MCX) to v0.2 (pmcx-based with modern Python practices).

## Overview of Changes

### Major Upgrades

1. **Python 3.13**: Upgraded from Python 3.8 to 3.13
2. **Package Management**: Now using `uv` instead of `pip`
3. **MCX Simulation**: Migrated from binary-based to `pmcx` Python library
4. **Configuration**: Pydantic v2 models for type-safe configuration
5. **Logging**: Structured logging with `loguru`
6. **Code Style**: Google-style docstrings and full type hints
7. **Project Structure**: Organized under `src/ijv_project/` layout

### Breaking Changes

❌ **Removed**:
- Binary MCX compilation requirement
- Shell script-based simulation workflows
- Direct calls to `mcx_ultrasound_opsbased.py`
- Old JSON configuration files

✅ **New**:
- `pmcx` Python library for simulations
- Pydantic configuration models
- Modern Python packaging with `pyproject.toml`
- Structured logging with `loguru`

## Installation

### Step 1: Update Python Environment

```bash
# Check Python version
python --version  # Should be 3.13+

# If not, install Python 3.13 via your package manager or pyenv
```

### Step 2: Install uv Package Manager

```bash
# Install uv (if not already installed)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Or via pip
pip install uv
```

### Step 3: Install Dependencies

```bash
# Navigate to project root
cd IJV-Project

# Install all dependencies (including dev and docs)
uv sync --all-extras

# Or install only core dependencies
uv sync
```

### Step 4: Verify Installation

```python
# Test pmcx installation
python -c "import pmcx; print(pmcx.__version__)"

# Test ijv_project package
python -c "from ijv_project import __version__; print(__version__)"
```

## Code Migration

### MCX Simulation: Old vs New

#### Old Approach (v0.1)

```python
# OLD: Using binary MCX via shell scripts and subprocess
import subprocess
import json

# Create config file
config = {
    "nphoton": 1000000,
    "vol": volume_data,
    # ... more config
}

with open("config.json", "w") as f:
    json.dump(config, f)

# Run via binary
subprocess.run(["./bin/mcx", "-f", "config.json"])
```

#### New Approach (v0.2)

```python
# NEW: Using pmcx with Pydantic models
from ijv_project.config import MCXConfig, MCXSource
from ijv_project.mcx_simulation import MCXRunner
import numpy as np

# Create typed configuration
source = MCXSource(
    pos=(30.0, 30.0, 0.0),
    dir=(0.0, 0.0, 1.0),
)

config = MCXConfig(
    nphoton=1000000,
    vol=volume_data,
    prop=properties_array,
    source=source,
)

# Run simulation
runner = MCXRunner(config)
result = runner.run()

# Or with CV criterion
result = runner.run_with_cv_criterion(
    cv_threshold=2.5,
    repeat_times=10,
)
```

### Configuration: Old vs New

#### Old Approach

```python
# OLD: Dictionary-based, no validation
config = {
    "subject": "Julie",
    "date": "20231012",
    "voxel_size": 0.25,
    # No type checking, easy to make mistakes
}
```

#### New Approach

```python
# NEW: Pydantic models with validation
from ijv_project.config import SubjectConfig

config = SubjectConfig(
    name="Julie",
    ultrasound_date="20231012",  # Validated as YYYYMMDD
    voxel_size=0.25,  # Type-checked as float > 0
)

# Automatic validation
try:
    bad_config = SubjectConfig(
        name="",  # ❌ Fails: empty string
        ultrasound_date="2023-10-12",  # ❌ Fails: wrong format
        voxel_size=-0.1,  # ❌ Fails: negative
    )
except ValidationError as e:
    print(e)
```

### Logging: Old vs New

#### Old Approach

```python
# OLD: print statements
print(f"Starting simulation with {nphoton} photons")
print(f"Error: {error_message}")
```

#### New Approach

```python
# NEW: Structured logging with loguru
from loguru import logger

logger.info(f"Starting simulation with {nphoton} photons")
logger.error(f"Simulation failed: {error_message}")
logger.success("Simulation completed!")

# Automatic file logging to logs/
# Configurable levels, rotation, retention
```

## Workflow Migration

### Old Workflow (Shell Scripts)

```bash
# v0.1: Run entire pipeline via shell script
cd mcx_sim
bash Run_MCX_Sim.sh
```

### New Workflow (Python Scripts)

```python
# v0.2: Use Python API directly
from ijv_project.mcx_simulation import run_simulation_pipeline
from ijv_project.config import ProjectConfig

config = ProjectConfig()
results = run_simulation_pipeline(
    subject_name="Julie",
    ultrasound_date="20231012",
    ijv_types=["ijv_large", "ijv_small"],
)
```

## API Changes

### Optical Properties

#### Old

```python
# Unstructured numpy arrays
props = np.array([[0.005, 1.0, 0.9, 1.37]])
```

#### New

```python
from ijv_project.config import OpticalProperties

props = OpticalProperties(
    mua=0.005,
    mus=1.0,
    g=0.9,
    n=1.37,
)

# Convert to array when needed
props_array = props.to_array()
```

### Simulation Results

#### Old

```python
# Parse binary output files
import struct

with open("output.mch", "rb") as f:
    data = struct.unpack(...)
```

#### New

```python
from ijv_project.mcx_simulation import SimulationResult

# Structured result object
result = runner.run()
print(result.flux.shape)
print(result.runtime)
print(result.nphoton)

# Save/load easily
result.save(Path("results.npz"))
loaded = SimulationResult.load(Path("results.npz"))
```

## Troubleshooting

### Issue: pmcx import error

```
ImportError: No module named 'pmcx'
```

**Solution**:
```bash
uv add pmcx
# Or
pip install pmcx
```

### Issue: CUDA not found

```
RuntimeError: CUDA not available
```

**Solution**:
- Verify CUDA installation: `nvidia-smi`
- Install CUDA Toolkit 11.7+
- Reinstall pmcx with CUDA support

### Issue: Old binary MCX still in use

```
FileNotFoundError: [Errno 2] No such file or directory: './bin/mcx'
```

**Solution**:
- Update code to use new pmcx API
- Remove references to binary MCX
- See "Code Migration" section above

## Gradual Migration Strategy

You can migrate gradually:

1. **Phase 1**: Install new dependencies alongside old code
2. **Phase 2**: Migrate one module at a time (start with MCX simulation)
3. **Phase 3**: Update configuration to use Pydantic models
4. **Phase 4**: Replace logging with loguru
5. **Phase 5**: Remove old code and dependencies
